# 2026-06-24 迭代记录：市场信号 ReAct 检索与信号分析

## 本轮目标

解决近期市场信号直接展示搜索结果导致的高噪声问题。项目工作台和赛道详情统一采用“检索 → 模型研判 → 下一轮检索目标”的 ReAct 流程，并允许用户设置最大搜索轮次。

## 完成事项

- 新增共享市场信号研究服务：
  - 每轮先按候选与项目/赛道主体的关联度做预排序。
  - 模型逐条输出相关性、0-100 分相关度及四到五句信号分析。
  - 模型可根据当前结果缺口生成下一轮分类检索词。
  - 明确过滤试题答案、教程、软件下载、泛百科和与主体无关的技术资料。
  - 模型调用失败时使用严格的确定性规则降级，项目级结果必须命中具体主体。
- 项目与赛道五类市场信号服务统一接入上述研究流程：
  - 默认最大搜索深度为 1，接口允许 1-5 轮。
  - 每类最多保留 4 条高相关结果。
  - 事件审计记录本次最大搜索轮次。
- 市场信号对象新增 `analysis` 字段，项目工作台和赛道详情均在每条信号下展示“信号分析”。
- 左下角用户头像由“直接退出”改为打开账户设置：
  - 可通过滑杆或步进按钮设置市场信号搜索深度。
  - 设置保存在浏览器本地，收集项目或赛道信号时自动带入请求。
  - 退出登录移动到设置窗口内。
- 新增 ReAct 编排测试，覆盖多轮目标续搜、深度 1 强制单轮和模型失败时过滤无关试题资料。

## 发现的问题

- 当前搜索深度是浏览器本地用户设置，尚未跨设备同步到用户账户。
- 模型能够决定下一轮关键词，但现有 Connector 仍以网页搜索为主；专利、论文的权威垂直数据源接入后，分类质量还可继续提升。
- 既有历史市场信号没有 `analysis`，前端保持兼容；用户再次收集后会写入新分析。

## 下一次迭代建议

1. 将搜索设置持久化为用户级后端配置，实现跨设备同步。
2. 在市场信号收集响应中暴露每轮检索轨迹和淘汰原因，供调试面板查看，不直接干扰投资研究界面。
3. 建立小型相关性评测集，统计噪声过滤率、有效信号召回率和不同搜索深度的成本收益。
4. 接入专利和论文垂直检索源，并给来源权威性加入独立评分。
