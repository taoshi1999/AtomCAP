## 本轮完成：PreferenceAdvice 聚合与审阅队列 API

目标：把 candidate/open 的 ExperienceEvent 聚合为 PreferenceAdvice，但不直接改 Preference。

完成事项：

1. 新增 `backend/app/services/preference_advice.py`
   - 筛选 `status in (candidate, open)`、`advice_generated=False` 且达到阈值的 ExperienceEvent。
   - 阈值：candidate、强信号、confidence >= 0.75、同向证据数 >= 3 任一满足即可进入建议。
   - 强显式信号可以在扫描后即时生成 advice，但仍进入人工审阅队列。
   - payload 使用 `objects/experience.py` 中的 PreferenceAdvice schema。
   - 从 `event.preference_impact.suggested_updates` 转成 `suggested_changes`。
   - source_summary 记录 message_count、user_action_count 和 time_window。

2. 更新 ExperienceEvent 生命周期
   - 标记 `advice_generated=True`。
   - 状态推进到 `advice_generated`。
   - 重复运行不得重复生成相同 advice。

3. 新增审阅队列 API
   - `GET /api/preference-advice`：pending 列表。
   - `POST /api/preference-advice/generate`：手动触发当前机构 advice 聚合。
   - `POST /api/preference-advice/{id}/review`：支持 accept / reject，部分接受留给后续偏好编辑流。
   - 审阅会写 `preference_advice.accepted/rejected` domain_event，并落结构化 UserAction。

4. 更新 worker cron
   - 新增 `generate_preference_advice_job`，每小时整点扫描所有机构并生成 pending advice。

5. 新增测试
   - `backend/tests/test_preference_advice.py`
   - 覆盖成熟事件生成 advice 并推进事件状态。
   - 覆盖接受 advice 后更新审阅状态、推进来源事件，并记录 domain_event / UserAction。

验证结果：

- `python -m compileall app worker` 通过。

## 下一次迭代 P1.5：采纳 Advice 后生成 Preference 新版本

目标：让 `accept` 不只是审阅状态变化，而是真的复用 `services/preferences` 写路径生成新的 active Preference 版本。

建议任务：

1. 新增 advice 应用服务。
   - 输入：`PreferenceAdvice`、当前 active `InvestmentPreference`。
   - 将 `suggested_changes` 应用到 `learned_preference` / `risk_boundary` 等字段。
   - 初版只支持 increase_weight / decrease_weight / exclude / review 中明确可自动应用的子集；无法自动应用的 change 标记为需要人工编辑。

2. 更新审阅逻辑。
   - accept 时调用 `set_active_preference` 创建新版本。
   - 更新 `PreferenceAdviceRow.applied=True` 与 payload.application。
   - 写 `preference.updated` 与 `preference_advice.applied` domain_event。
   - 来源 ExperienceEvent 保持 accepted。

3. 补测试。
   - sector/subsector weight 调整能生成新 Preference 版本。
   - risk_boundary change 能写入风险边界。
   - 不支持自动应用的 change 不应污染 Preference。
   - 重复 accept 不重复创建版本。

验收标准：

- 接受一条可自动应用 advice 后，`GET /api/preferences` 返回新版本。
- PreferenceAdvice payload 中记录新版本号。
- 拒绝 advice 不改 Preference。
